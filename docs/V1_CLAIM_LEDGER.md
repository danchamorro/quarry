# Quarry v1.0 Claim Contract Ledger

This ledger tracks every quantitative, behavioral, and platform target for Quarry v1.0 as a measurable engineering contract. Every entry uses a paraphrased summary tied to a stable **Claim ID** (`C01`–`C44`). No public claim is considered ready for release documentation until its **Disposition**, **Owner Decision Ref**, and **Evidence Status** are satisfied and reconciled in Phase 9.

## Governance Separation

This ledger keeps three concepts explicitly distinct:

1. **Owner Decisions (`T1`–`T21`):** Product, scope, architecture-policy, and distribution approvals granted by the project owner. An owner decision authorizes work toward a target; it never substitutes for empirical verification.
2. **Evidence Status (`verified` | `partial` | `unverified` | `blocked`):** Objective measurement state backed by committed test results, benchmark manifests, CI runs, or verification reports.
   - `verified`: Passing reproducible evidence exists on the required venue and meets the pass threshold.
   - `partial`: Implementation or partial measurements exist, but the target scale, platform, or threshold is not yet fully proven.
   - `unverified`: No qualifying evidence exists yet.
   - `blocked`: Blocked on an unresolved technical gate, missing hardware venue, or unfulfilled policy prerequisite.
3. **Per-Task Authorizations:** Explicit execution gates required before specific implementation or testing actions begin, independent of roadmap approval:
   - **GPUI implementation kickoff (Phase 4B-1):** Updating local repository rules / granting task-level authorization before modifying `apps/quarry-gpui/`.
   - **GPUI packaging cutover (Phase 4B-3):** Explicit sign-off after parity, accessibility, and zero-HTTP gates pass.
   - **Third-party notices regeneration (T19):** Explicit owner approval whenever workspace dependencies change notices.
   - **Bare-metal GUI / 120 Hz / physical hardware runs (T18):** Explicit task-level approval before any desktop app run outside the configured macOS VM.
   - **Distribution channels & release publication (T16, T17):** Explicit owner approval per package manager, download host, and release publication.

## Field Definitions

- **Disposition:** `build` (implement and verify to threshold) | `rephrase` (scope public wording to verified design/venue) | `cut` (out of scope for v1.0).
- **Venue:** `host-bare-metal` | `VMPal-VM` | `CI-runner` | `owner-booked-hardware` | `unmeasurable->rephrase`.
- **Consuming Phase:** The roadmap phase responsible for satisfying the target and writing any required ADR amendments.
